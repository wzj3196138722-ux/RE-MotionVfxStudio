# MotionVfx Live 使用教程

[项目介绍](../README.md) · [English](tutorials.en.md)

适用于 **0.8.5**。以下按钮名称按游戏内 D2D 工作台编写。先完成安装并启用 REFramework 的 Loose File Loader，启动后台和游戏；第一次操作建议在训练场完成。

## 界面怎么用

左侧分为动作记录、特效记录、特效编辑、PFB 编辑、时间与回看。顶部有资源预缓存、文件、编辑、设置；主要应用按钮随当前页面变化。

拖动左上 Logo 标题区移动窗口，拖动边缘调整大小。隐藏后，点击贴边 Logo 小球恢复；游戏中可先按 Insert 开启 REFramework 鼠标。设置中可以居中窗口、调整缩放和切换属性/参数中英文名称。未释义字段会保留原名，搜索可使用原名。

文件窗口中，单击选择、双击文件夹进入、双击文件打开。Enter 打开、Esc 取消、Alt+左/右后退或前进、Alt+上进入上级、F5 刷新。导入多个素材时可以 Ctrl/Shift 多选；地址栏可粘贴中文完整路径。

## 1. 第一次修改真实触发的特效

目标：修改某个动作确实调用的 EFX，在游戏内确认变化，然后导出或恢复。

1. 打开「动作记录」，点击「开始记录调用」。当前动作即使没有开始记录也会实时显示；记录用于保留后续选择需要的信息。
2. 隐藏界面，只做一次目标动作，例如攻击、装填或鬼人化，再打开界面点击「结束记录调用」。先做简短记录，便于定位。
3. 打开「特效记录」，查看该动作的关联特效。若筛选后为空，点击「全部特效」检查本次已捕获的资源。时间相近不一定代表直接调用，优先使用归属与来源已确认的记录。
4. 对目标资源点击「打开并编辑」。先检查完整资源路径，再展开 **Group → 特效块（Entry）→ 属性**。多个动作可能共用这个文件。
5. 选一个容易观察的参数，记下原值，小幅修改后点击该参数的提交按钮。输入框里打了字不等于已提交。
6. 点击顶部「应用特效参数」，等待操作结束。隐藏界面并重新做原动作；已存在的粒子不一定立即变成新版本。
7. 检查是否报告角色实际创建了新版本，再观察画面是否达到预期。只有“应用成功”还不足以证明改中了目标效果。
8. 要保留成果，用顶部「文件 → 导出文件」选择输出位置。完成后点击「停止并还原」并等待完成。

从记录打开时，编辑器读取当前游戏安装中该逻辑路径的有效文件，包括松散文件及 PAK 覆盖顺序。这不是直接导出游戏内存。打开本地同名文件也不代表它就是角色当前使用的版本。

## 2. 颜色、曲线、分组与特效块

### 颜色和组合参数

选择带显式 RGBA 颜色的属性，上方的颜色控件与下方 R/G/B/A 数值互相同步。明确的 `via.Color` 按 0–255 编辑，例如 `[0,180,255,255]`；亮度/强度是独立参数，不要把它当成 Alpha。

修改后使用该颜色区域的提交按钮，一次提交四通道，撤销一次也恢复四通道。普通四维向量不会自动当作颜色。XY、XYZ 及可识别的普通/随机值会组合展示，实际写入仍对应原字段。

### 表达式曲线

1. 选择如 `SpawnExpression` 的属性，展开「表达式曲线 · 公式与数值」。
2. 先确认通道名称，再查看每个节点的已提交值。例如 `spawnNum` 与 `spawnNumRange` 是不同通道，都可能出现 `Lerp.起始值 from`。
3. 每次只改一个明确的数值，点击「提交数值」，再应用并重做目标动作。

不要照搬别人的 Entry 序号或示例初值；MOD 和游戏版本会改变内容。没有可见变化时，先检查是否触发了该 Group/块、目标通道是否实际参与计算，而不是不断放大数值。当前工具不保证所有复杂表达式结构都能自由增删节点。

### 复制与粘贴特效块、属性

「复制 / 粘贴」固定显示在参数面板顶部，会显示已复制的内容、来源文件和当前粘贴位置。

**复制整个特效块：** 在左侧选中来源块 → 点「复制特效块」→ 选择目标 Group 的「选择分组 / 编辑备注」或目标块 → 点「粘贴为新特效块」。选择目标块时，新块加入该块所属的 Group；选择文件属性时，粘贴为未分组的新块。新块会自动选中，并使用不重名的 `_copy` 名称。

**复制一项属性：** 选中来源属性 → 点「复制此属性」→ 选择接收它的块或 Action → 点「粘贴属性到此块」。如果目标已有同类型属性，按钮会改为「替换同类型属性…」；检查目标提示后，再点「确认替换属性」。存在多项同类型属性时，要先选中具体要替换的那项。Action / PlayEmitter 内嵌块的属性也支持这套操作；整个 Action 不作为特效块复制。

可以复制后切换到另一个 EFX 文件。复制的是当时已提交的内容，之后修改来源不会改变这份快照。未提交输入需先提交或还原；复制缓冲区只在当前会话保留，可用「清空已复制内容」清除。

粘贴后通过顶部「编辑 → 撤销」可恢复，点击「应用特效参数」才会更新游戏中的资源。贴图、模型等引用路径保留原值，不会自动复制依赖文件。EFX 格式版本或文件级表达式／变量表不兼容时会说明原因并拒绝粘贴，保留原文档。

### Group 备注、删除和单块恢复

- 「选择分组 / 编辑备注」中的备注只改变编辑器标签，支持中文。原始组名仍保留，动作调用使用原始组名。备注单独保存，撤销 EFX 参数不会撤销备注。
- 选中块或属性后，可使用「删除当前特效块」或「删除当前属性」。通过编辑器的结构操作删除，不要手工改二进制计数或残留字节。导出前可重新打开导出副本检查结构。
- 「还原当前特效块」回到该块本次编辑的原始状态，其他块保留；新建块没有原始状态时会被移除。操作可以撤销。
- 文档变化与游戏引用变化是两件事：编辑完成需要应用；「停止并还原」恢复游戏引用，不是撤销所有已提交参数。

<a id="action-slots"></a>
## 3. 为动作添加特效

这里同时编辑**动作的触发信息**与**对应 PFB 的特效槽位**，因此必须先找对当前动作实际使用的 PFB。

1. 记录目标动作，在动作列表选中它，进入「动作特效槽位」。
2. 点击「核实当前动作的 PFB」。在实际列出的角色通用或武器外部容器中选择目标，再点「编辑此 PFB 的动作槽位」。换装备、换场景后重新核实，不能凭武器名猜一个 PFB。
3. 输入要调用的 EFX 游戏路径，例如你已捕获资源的完整 `art/.../文件.efx` 路径，或预缓存别名。不要填本机 `C:\...` 路径。
4. 点击「读取此 EFX 的全部 Group」，从「Group 分组」选择该 EFX 原始分组名，或按需要选择「全部 / 不指定分组」。每次更换 EFX 路径后重新读取。
5. 在「挂载对象」选人物或当前武器，再选实际对象和骨骼。人物的 `RelationChildId` 为 -1；武器 ID 从当前对象检测，不能拿武器编号代替。下拉列表没有目标时，先重新核实来源。
6. 选择挂载方式。身上光效或刀光通常使用「持续跟随挂点」；地面标记通常使用「仅在触发时定位」。不指定骨骼表示对象原点，不代表自动吸附脚底或地面。
7. 填「出现帧」与「触发区间结束帧」。它们是该动作内部的帧数；动作衔接可能从中途进入。第一次可用界面显示的完整有效帧范围确认触发，再缩短区间。
8. 选择寿命方式。「随触发区间或动作结束」适合随动作退出；「独立寿命（切换动作继续播放）」适合脚印等需要留下的效果，再填写每次触发后的最长寿命。EFX 自身仍可以提前结束。
9. 展开「选择挂接模板（来自上述 PFB）」，点击一个用途接近的原有槽位。
10. 点击「添加特效槽位」→「热重载到游戏」，等待完成，再重新执行目标动作。后续修改需要再次热重载。

**为什么必须选模板？** PFB 槽位不仅有路径和骨骼，还包含偏移、旋转、缩放、颜色、镜像、延迟及自定义引擎参数。模板给新槽位提供完整结构。新槽位获得独立编号；你填写的 EFX、Group、对象、骨骼、帧区间和寿命覆盖相应设置，不修改原模板，也不复制原动作的触发帧。位置或大小异常时，应检查模板继承的参数，必要时换同用途模板。

**脚印示例思路：** 选实际触发的移动片段，选合适的脚部骨骼、仅触发时定位、独立寿命，再检查 EFX 的落地位置和朝向。荒野会随地形和移动方向切换不同动作，给一个动作加槽位不会自动覆盖所有走路片段；先记录实际需要的片段，逐个验证。触发区间也不等于每帧生成一次。

删除一个新增槽位用「删除此槽位」；整组撤回用「还原并清除新增槽位」，它会清除本次会话新增槽位并恢复动作表与 PFB，保留 EFX 参数文档。导出用「导出动作文件与对应 PFB」，两份文件分别选择路径，可跳过其中一份；完整分发通常仍需要安装双方修改及依赖。

<a id="pfb"></a>
## 4. 独立 PFB 编辑

通过顶部「文件 → 打开 PFB 文件」或左侧 PFB 编辑页打开文件。编辑器按实际组件识别类型：

| 类型 | 主要操作 |
|---|---|
| 装备 PFB | 添加特效 PFB、Chain/Chain2、CLSP、JCNS 资源槽 |
| 特效 PFB | 复制/粘贴槽位、编辑参数、删除、撤销和重做 |

填写可由游戏读取的逻辑路径，提交参数后可单独导出。需要热重载时，还必须核实当前角色或装备实际使用的目标 PFB。打开任意本地文件并不意味着可以替换任意角色对象；来源不匹配会拒绝应用。

装备实例重建、每种组件组合与各武器效果尚未全部实机验证。首次使用新类型时保留原文件，从单槽位的小改动开始，检查热重载和还原，再扩大修改。

<a id="precache"></a>
## 5. 预缓存外部素材

素材需要已经转换为荒野可读取的游戏格式，并保留正确的版本后缀，例如 `.tex.<版本号>`。此功能不负责把 PNG、FBX 等普通格式转换为游戏文件。

1. 打开顶部「资源预缓存」，点「选择外部文件」。保留素材原有的 `natives/stm` 或 `art` 目录结构，便于解析依赖。
2. 选中目标文件后，留空自定义路径以自动生成 `art/` 别名；自定义时一次选一个文件。
3. 点「加入预缓存」，检查列表和依赖，再用「预加载资源」检查加载状态。
4. 点击「复制路径」，将别名填入 EFX 对应的资源字段并提交；也可从资源参数的「从预缓存选择」进入，再「填入所选参数」。
5. 应用 EFX，重新触发动作确认结果。
6. 原素材更新后点击「重新读取并热重载」。先提交或还原参数草稿；已经应用的当前 EFX 会重新应用，新创建的实例使用新版本。

`art/...` 是游戏资源的逻辑名字，不是电脑上的真实目录。后台保存独立副本并生成预览版本，不覆盖原素材。自动关联仍需要能找到完整依赖；结构或版本无法解析时，请依据错误修正，不能靠重试补齐未知结构。

导出单个 EFX 不会把所有贴图、材质和网格打进 EFX。对外分发时，必须同时提供它实际引用的依赖，并保持安装后的逻辑路径一致。

<a id="time-replay"></a>
## 6. 暂停、慢放与倒放

### 实际游戏时间

「时间与回看」提供 0.1×、0.25×、0.5×、1× 和暂停/继续。继续会恢复暂停前所选速度。编辑完点击「停止并还原」交还时间控制；仅选 1× 不等于结束接管。

设置中可设暂停快捷键，例如 `Ctrl + Shift + Alt + P`，支持 1–8 个不同键。保存后勾选「调试模式」，每次按完必须全部松开，再按一次切换暂停/继续。启用时组合里的每个键会被编辑器接管，即使只按部分键也不再用于游戏；关闭调试模式恢复游戏控制。文本输入期间暂不触发，Insert 和系统保留组合不可绑定。

### 录制画面与回看

1. 选择 5/15/30 秒，点「开始录制画面」。工作台隐藏后有约 3 秒准备时间。
2. 保持游戏在前台并执行动作；切到其他程序时暂停采集。也可提前「结束并保存录像」。
3. 等待保存，在「时间与回看」点「正放重播」「倒放」或「前一帧 / 后一帧」。可调整回看倍率、拖动进度。
4. 点「打开录像保存文件夹」查看文件；重载后可用「读取最近录制」。

保存位置为 `游戏目录/reframework/images/MotionVfxLive/replays/<片段编号>/`，内容是 JPG 帧与 `replay.json`。目标上限为 20 帧/秒、宽度 1280 像素，无音频，不是标准 MP4。界面会显示实际帧数与路径；采集失败不会生成成功的空录像。**倒放的是这些画面，不会倒退游戏或粒子模拟。**

<a id="export-restore"></a>
## 7. 导出、还原与会话

| 操作 | 结果 |
|---|---|
| 提交参数 | 修改编辑文档，尚未自动证明游戏中生效 |
| 应用特效参数 / 热重载 | 发布预览版本并替换已核实的游戏引用 |
| 文件 → 导出文件 | 将当前编辑页文件写到你选择的位置；覆盖已有文件需确认 |
| 撤销 / 重做 | 修改文档的编辑历史 |
| 还原当前特效块 | 仅恢复当前 Entry 的本次原始状态 |
| 停止并还原 | 停止记录/预览，恢复游戏引用和时间状态；不等同于撤销 EFX 文档 |

已提交文档在切换文件时保留。未导出的编辑按本次游戏会话使用，不应把它当作永久存档。关闭游戏或更新前，导出需要保留的 EFX、动作及 PFB，等待资源与场景还原完成。

Group 备注单独保存在 `游戏目录/reframework/data/MotionVfxLive/group-notes.json`。录像和预缓存也有各自文件。旧后台文档恢复副本不包含所有输入草稿、动作槽位或撤销历史，不能替代导出。

<a id="mcp"></a>
## 8. 让 AI 通过 MCP 修改特效

安装后点击「打开安装目录」，找到 `mcp-config.json` 与 `mcp-config.toml`。将适合你的客户端的服务器段合并到客户端 MCP 配置，保留其他服务器。配置包含真实安装路径，不要把 JSON 当聊天附件代替接入。

这是本地 **stdio MCP**，由 AI 客户端启动包内 `mcp/VfxStudio.Mcp.exe`，并传入 `--config` 与 `runtime-config.json`。后台和游戏仍需另行启动；手工双击 MCP EXE 不会打开编辑器。

建议先在界面完成一次记录，并打开目标 EFX，然后给 AI：

> 使用 MotionVfx MCP 检查我当前打开的 EFX，先读取状态、来源、块与实际字段。把我指定的目标颜色改成青色，保留透明度和亮度，其他内容不变。不要覆盖未提交输入。修改前记录旧值，使用最新 expectedRevision，写入后回读并保存独立副本。应用后让我重做原动作，确认角色实际创建新版本，再由我确认画面。最后恢复资源与场景，报告保存路径和验证结果。

常用工具顺序：

1. `motionvfx_status` → 检查连接、当前文档与草稿。
2. `motionvfx_list_actions` / `motionvfx_list_effects` → 定位记录；需要时 `motionvfx_open_effect`。
3. `motionvfx_inspect` → 获取真实目标编号、字段路径、颜色组或曲线。
4. `motionvfx_set_field` / `motionvfx_set_color` → 使用最新 `expectedRevision` 修改，再回读。
5. `motionvfx_save_copy` → 保存副本并记录返回路径。
6. `motionvfx_apply` → 应用；重做动作后查询状态，`verification.phase=created` 才说明角色创建了这次新资源。
7. `motionvfx_restore` → 检查还原结果。

分组备注使用 `motionvfx_set_group_note`，它不改原始分组名，也不进入 EFX 撤销历史。需要慢放时使用 `motionvfx_scene_time`。MCP 当前不提供任意脚本执行、画面录像、磁盘素材导入或动作/PFB 槽位写入工具；这些通过界面操作。

若返回 `stale_revision`，先重读；`drafts_present` 表示人工输入待处理。超时或 `uncertain:true` 时不要自动重复写入或删除请求记录重试，原操作可能已经完成。完整参数协议见发布包内「AI修改特效教程.md」与 `mcp-tools.json`。

## 常见问题

| 现象 | 下一步 |
|---|---|
| 后台未连接 | 启动桌面 MotionVfx Live；检查安装使用的游戏目录 |
| 界面隐藏了 | 按 Insert 开启鼠标，点击贴边小球；也可从 Script Generated UI 找回/居中 |
| 记录了但无法重播 | 调用记录不是录像；使用「时间与回看 → 开始录制画面」 |
| 特效列表为空 | 执行实际带特效的动作，检查「全部特效」；切换装备后重新记录 |
| 已应用却无变化 | 重新触发目标动作，核对 Group、Entry、实际新版本创建状态和有效来源 |
| 添加槽位按钮不可用 | 检查已读取 Group、实际挂载对象、模板与有效帧范围；查看页面错误 |
| 换装备后热重载失败 | 重新记录并核实动作/PFB 来源，不沿用旧对象 |
| 还原失败 | 保留当前游戏与脚本，保存错误和日志；不要 Reset scripts 清空尚未还原的备份 |
