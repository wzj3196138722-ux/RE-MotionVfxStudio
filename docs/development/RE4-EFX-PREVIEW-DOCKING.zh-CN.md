# RE4 离线预览：面板停靠

预览窗口的五个面板（主面板、属性目录、EFX 属性编辑、EFX 节点图、曲线时间轴）可以停靠到窗口四边，也可以拖出来重新浮动。3D 画面只渲染在停靠之后空出的中央区域，不再被面板挡住。

## 用法

- 拖动面板的标题栏（或停靠后的标签页），靠近窗口边缘或其他面板时会出现停靠提示，松开即停靠。拖离停靠区域就变回浮动窗口。
- 多个面板可以停靠在同一处，以标签页切换；分隔条可以拖动调整大小。
- 第一次打开时自动排出默认布局：主面板在左（约 24%，下方 45% 是属性目录），属性面板在右（约三分之一），节点图和曲线时间轴并排在下方（约 36%）。
- 属性目录加入之前保存的布局里没有它：第一次打开时把它作为标签页停在主面板旁边。
- 主面板的“重置布局”恢复默认布局，并重新打开节点图、曲线时间轴和属性目录。
- 布局保存在 `runtime/re4-preview/imgui-layout.ini`，下次打开时恢复。删除这个文件也会回到默认布局。

## 实现

- 停靠用 Hexa.NET.ImGui 的 docking 分支：`ImGuiConfigFlags.DockingEnable` 必须在第一次 `NewFrame` 之前设置，所以放在 `ImGuiController` 的 `onConfigureIO` 回调里，同时设置布局文件路径（ImGui 持有这个指针，整个窗口生命周期只分配一次）。
- 每帧在场景绘制之前调用 `DockSpaceOverViewport`（固定 id，`PassthruCentralNode`），再用 `DockBuilderGetCentralNode` 取中央节点的矩形，按 `DisplayFramebufferScale` 换成帧缓冲像素。
- HDR 管线按中央节点的尺寸渲染，投影的宽高比也随之改变；最后把结果贴到窗口里的对应矩形，其余部分清成背景色。场景着色器（软粒子、Distortion、Billboard2D）用的屏幕坐标都相对于 HDR 目标，所以不用修改。
- 画界面之前把 GL 视口恢复成整个窗口，否则界面会被压缩进场景区域。
- 中央节点是空的穿透区域，鼠标在上面时 ImGui 不占用输入，相机的旋转、平移、缩放照常可用。
- MCP 截图和 `inspect` 像素读取的都是中央区域的画面（尺寸等于中央节点）。
- 冒烟、性能测量、延迟测量和空闲测量模式不启用停靠，保持整窗渲染，测量结果与以前可比。

## 验证

- 删除布局文件后启动：默认布局正确，场景位于中央区域；第 90 帧画面正常，管道截图尺寸 640×510，等于中央区域的大小。关闭后布局文件写入了停靠数据。
- 回归：MCP 端到端 56/56（窗口启用停靠）、Re4PreviewTests、播放控制（含原生）、通用编辑、P2 全部通过。
- 没有用鼠标实际拖动面板停靠或浮动；这部分是 ImGui 自带的交互。
