# RE4 离线预览 P2：参数编辑与通用属性面板

P2 已实现：单个已有 Billboard3D entry 的通用属性面板、字段批量应用、颜色编辑；应用后保留 tick 和播放／暂停状态；同一辅助进程内快速重载；撤销/重做；完整 EFX 副本保存和重新打开；修订发布与预览失败恢复。通用面板可选择该 entry 已有的属性，不限于 Billboard3D、Life；可编辑状态与条件由后台 Inspector 决定。局部重建、属性增删与拖入组装仍未实现。

## 启动和操作

仓库根目录运行：

```powershell
dotnet run -c Release --project VfxStudio.Re4Preview -- --fixture bb2
```

原有 `--fixture bb`、`--efx <文件> --offset <十六进制条目偏移>`、`--exe`、`--python`、`--resources` 继续可用。构建会同时构建并复制 LiveEditor 后台，启动时自动创建独立的离线会话，无需运行游戏。

右侧“EFX 属性编辑”面板（详细范围与验证见 [通用属性面板](RE4-EFX-PREVIEW-P2-GENERIC.zh-CN.md)）：

1. 从下拉列表选择当前发射器的属性。初始选择 TypeBillboard3D，可修改 Color、ColorRange、ColorRate、SizeScalar、SizeX、SizeY 等字段；范围颜色仍只在文件属性启用随机颜色时生效。字段按路径分组，可搜索、清空搜索、显示/隐藏只读字段及翻页；切换属性会清空搜索。
2. 修改字段后点“应用本属性修改”。同一属性的 1–64 个变化字段作为一个事务，一次撤销全部恢复；颜色四通道计为四个字段。Life 的 AppearFrame、KeepFrame、VanishFrame 可同时修改 min/max；数值类型和整数区间由后台校验，失败整笔回滚并保留草稿。未应用草稿需要先应用或放弃，才能切换属性；外部修订出现时旧草稿保留，但不能提交覆盖新修订。
3. 参数应用、撤销、重做或同一文档的外部修订后，保留修改前显示的 tick 和播放／暂停状态：原来播放则继续播放，原来暂停则仍暂停；加载期间连续到达的新修订也保留这一状态。打开源文件、打开已存副本或点击“重载并重播”时从 tick 0 开始。相机、场景和预览精度保留；未应用的表单值不会修改文档。
4. “保存副本”保存整个 EFX；路径可留空，自动保存到当前会话的 saved 目录。显式路径必须是绝对路径并使用 `.efx.3539837` 后缀；不覆盖已有文件和导入来源，也不接受游戏目录和解包目录（`--resources`）下的路径，否则游戏会把它当作松散文件加载。窗口在发送前检查，后台以 `--protect` 参数收到同一组目录并独立拒绝，经过符号链接或目录联接的保存路径一并拒绝。面板显示保存位置，“打开已存副本”可重新打开。
5. “重试预览”重新发布当前文档并重载，不重复应用修改或增加撤销记录。“重载并重播”重载当前已发布的快照。“重新打开源文件”可在修正源文件后重试打开。打开失败或打开后选择发射器失败时，面板不再保留上一个文档的参数与属性下标，编辑按钮在刷新出新文档的参数前不可用。

尺寸字段控制出生参数；文件里已有的 ScaleAnim 仍继续作用。例如把出生尺寸中心放大两倍，不一定会让某一年龄的最终尺寸严格乘二，因为动画的加法项没有随之改变。

单次修改到原生帧更新（bb2，应用颜色与尺寸后读回 tick 45）实测 150–175 ms，在 200 ms 目标内。其中 LiveEditor 应用、校验和发布约 110–140 ms，原生重载约 30–37 ms，重跑到 tick 45 约 5 ms。数字来自 `tools/Re4PreviewP2Tests` 输出的 `TIMING` 行与 `results.json`；重跑耗时随当前 tick 增长。连续修改会合并待加载目标，已开始的原生加载先结束，再加载最新目标。

快速重载的做法：辅助进程第一次加载时映射 re4.exe、安装运行时并记录不含发射器的基础快照；之后每次加载先恢复基础快照（约 15 ms），再解析 entry、构造发射器并记录新的加载后快照（约 15 ms），不再重启进程、不再重新映射镜像。同进程重载与新进程加载的逐 tick 粒子数组摘要相同（bb、bb2、去掉 FixRandomGenerator 并设全局种子三种情形，`tools/Re4PreviewTests`）。同进程重载失败时，客户端改用新进程重试一次，并在面板显示原因。

## 文档、发布和显示

LiveEditor 的 EditorEngine 是唯一文档和撤销权威。通用表单通过 `inspect` 读取字段/颜色描述；窗口只保留带文档 ID、修订、entry 和属性下标的文本草稿，通过 `set_fields` 提交同一属性的批量修改。旧文档或旧修订的草稿会被拒绝。原有颜色/尺寸与 Life 的专用客户端接口继续供既有回归和基准使用。

默认会话位于 `runtime/re4-preview/<时间戳_GUID>/`，包含：

- `mailbox/`：独立后台状态与命令响应；与游戏内编辑会话分开。
- `mailbox/offline-preview/revision_*.efx.3539837`：经过完整文件保存/再读验证的不可变修订文件。
- `mailbox/offline-preview/preview.json`：原子发布的当前清单，包含文档标识、修订号、完整文件 SHA256、选中条目位置/ID及其新的字节偏移。
- `saved/`：用户保存的副本。

后台不传 `--game-root`，不轮询游戏进程，也不发布到游戏目录。游戏来源保持只读。会话目录在窗口关闭后保留，便于找回已发布或已保存文件；未提供跨重启恢复撤销栈的功能。`--session` 可指定一个新的会话目录，`--editor-backend` 可指定后台 DLL；它们不用于接管其他正在运行的后台。

面板分别显示“文档 rN”和“画面 rM”。只有新修订的原生帧成功读回后才替换旧画面；过时的加载/帧结果释放后丢弃。发布或加载失败保留已有文档和上一幅有效画面，显示错误，允许修正、撤销或重试。未应用草稿遇到外部修订会保持原值并要求刷新；干净表单会自动同步。程序监视本会话的清单变化，可接收同一后台通过邮箱协议完成的其他编辑，但没有自动接管游戏内或已有 MCP 会话。

发布失败不等同于编辑失败：编辑可能已经提交。响应中的 `offlinePreviewError` 会说明发布错误；调用 `publish_offline_preview` 只重发当前文档，避免重复修改。

## 验证

```powershell
dotnet run --project tools/Re4PreviewP2Tests
dotnet run -c Release --project tools/Re4GenericEditorTests
dotnet run --project tools/Re4PlaybackTests -- --native
dotnet run --project tools/Re4PreviewP1Tests
```

`Re4PlaybackTests --native` 已验证修订重载保留播放／暂停状态及 tick 45，原生粒子摘要不变；还覆盖加载期间合并修订、暂停在时间轴末尾、显式重播与故障暂停。2026-11-15 已补真实窗口验收与窗口绘制延迟实测，见 [P2 窗口验收记录](RE4-EFX-PREVIEW-P2-ACCEPTANCE.zh-CN.md)。

窗口计时可用 `--measure-latency` 开启，右侧参数提示已更新为保留 tick 和播放／暂停状态。每次应用、撤销、重做和重试预览，会记录对应修订从接受命令到首帧 GPU 完成的时间，输出到会话目录的 `latency.jsonl`、`latency-summary.json` 和 `latency-environment.json`。GPU 完成包含诊断同步开销，尚未包含交换缓冲、桌面合成与显示器扫描。

重复测量使用：

```powershell
dotnet run -c Release --project VfxStudio.Re4Preview -- --fixture bb2 --quality full --latency-benchmark --latency-repeats 20
```

此模式在真实窗口中自动修改颜色倍率，覆盖 tick 45、300、900，每组预热 2 次并测量 20 次。先走与面板相同的提交路径，再由后台写入任务提交修改，让窗口通过清单轮询发现修订。后一条用于测量外部修订路径，不表示 MCP 已接入，也不替代按钮的手动验收。冷启动和拖动到目标 tick 不计入修改延迟。

清单轮询默认 **25 ms**，可用 `--manifest-poll-ms <整数>` 调整（1–60000 ms）；`--manifest-poll-ms 250` 可用于对照旧设置。实际频率受窗口更新频率限制，每次更新最多读一次，没有文档清单时不轮询。发现新修订后立即排队加载已发布的快照，后台 status 查询同时刷新参数表单；快照仍先校验 SHA256，表单查询期间不允许提交编辑，同一 Key 的 status 回复不会再次重载。

通用面板接入后的 bb2 三个目标 tick 复测，窗口提交 P95 为 162–179 ms，外部修订 P95 为 120–129 ms（每组 20 次正式样本）。仍以首帧 GPU 完成为终点，不包含交换缓冲和桌面合成；不能推广到所有文件与任意 tick。批测使用原有专用客户端操作入口，另有真实按钮对通用提交入口的手动验收。

诊断模式会另外输出 `manifest-poll-stats.json`，记录读取清单的次数与处理墙钟耗时。可用 `--idle-benchmark 10 --quality full` 在暂停的真实窗口中测 10 秒空闲开销，完成后自动退出并输出 `idle-benchmark.json`；与其他自动测量模式互斥。无效轮询参数会打印原因，以退出码 2 正常结束。

`dotnet run -c Release --project tools/Re4LatencyTests` 验证修订匹配、过期帧拒绝，以及首帧 GPU 完成早于后台回复时仍保留首帧时间，只等待 GPU 一次。外部修订的 JSONL 增加 `manifestObservedMs`；`responseMs` 是独立的应答时间，可能晚于加载或 GPU 完成，不能再假设所有阶段都排在应答之后。

P2 集成测试使用真实 bb2 整个文件，覆盖：

- 序列化为完整 EFX、正确定位选中 entry，其他 entry 的内容不变；游戏原文件摘要不变。
- 修改后的重载必须复用辅助进程，并输出应用、原生重载、重跑三段耗时。
- 颜色、尺寸和 ColorRate 到达实际原生粒子/属性块；Life 延长粒子寿命。
- 撤销恢复完整文件字节及同 tick 原生粒子数组 SHA256，重做可恢复修改。
- 保存、再读取、重新打开；保存到已打开的副本时按“导入来源受保护”拒绝（只认这一错误信息）；保存到游戏目录时窗口拒绝，保存到测试用受保护目录时后台拒绝，均不生成文件；拒绝旧修订。
- 无效 Life 区间：表单拒绝；绕过表单的原始 `set_fields` 被后台拒绝，修订号、发布摘要和 Life 参数不变。
- 人为锁住清单文件制造发布失败，修订和撤销记录保留；重试发布不重复编辑。
- 篡改已发布快照时 SHA256 校验拒绝加载；重新发布后原生预览可恢复。

真实窗口已操作颜色倍率输入（包括 Ctrl+A/粘贴）、应用、撤销、保存副本及打开副本；观察到 r2 的画面更新、r3 撤销恢复以及 r4 保存副本重载。连续外部发布 r5/r6 时，加载阶段保留 r4 画面，最终显示 r6，未被旧加载结果覆盖。数字编辑测试同时修复了共享 ImGui 控制器的修饰键事件上报。

原有 LiveEditor 剪贴板回归通过 57 项检查；为让当前后台可编译，旧测试中的 Life `r/s` 名称已改为当前 `min/max` 名称。常规 P1 原生与播放控制回归继续保留。

剩余渲染边界与 P1 相同：单 entry、BlendType 0/1，完整外观链和游戏录像对照未完成；完整分辨率一万粒子 60 fps 仍未达到。属性模块组装只保留在设计计划中，本阶段没有实现。
