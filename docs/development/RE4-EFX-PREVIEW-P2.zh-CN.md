# RE4 离线预览 P2a：最小参数编辑闭环

P2a 已实现：单个已有 Billboard3D entry 的颜色、尺寸、Life 编辑；应用后在原 tick 继续；撤销/重做；完整 EFX 副本保存和重新打开；修订发布与预览失败恢复。快速重载、局部重建和拖入属性组装仍未实现。

## 启动和操作

仓库根目录运行：

```powershell
dotnet run -c Release --project VfxStudio.Re4Preview -- --fixture bb2
```

原有 `--fixture bb`、`--efx <文件> --offset <十六进制条目偏移>`、`--exe`、`--python`、`--resources` 继续可用。构建会同时构建并复制 LiveEditor 后台，启动时自动创建独立的离线会话，无需运行游戏。

右侧“EFX 参数编辑”面板：

1. 修改出生颜色、范围颜色、颜色倍率，或整体尺寸/宽度/高度的中心与幅度，然后点击“应用颜色和尺寸”。范围颜色仅在文件属性启用随机颜色时生效。
2. 修改 Life 的淡入、保持、淡出最小值/最大值，然后点击“应用 Life”。单位为帧，当前输入要求 `0 ≤ min ≤ max ≤ 32767`。后台对任何被修改的整数区间（`MinMaxI`）同样拒绝 max < min，整笔修改回滚；绕过表单直接发 `set_fields` 也不例外。
3. 参数应用、撤销、重做后，等待加载完成，从修改前显示的 tick 继续播放。打开源文件、打开已存副本或点击“重载并重播”时从 tick 0 开始。相机、场景和预览精度保留；未应用的表单值不会修改文档。
4. “保存副本”保存整个 EFX；路径可留空，自动保存到当前会话的 saved 目录。显式路径必须是绝对路径并使用 `.efx.3539837` 后缀；不覆盖已有文件和导入来源，也不接受游戏目录和解包目录（`--resources`）下的路径，否则游戏会把它当作松散文件加载。窗口在发送前检查，后台以 `--protect` 参数收到同一组目录并独立拒绝，经过符号链接或目录联接的保存路径一并拒绝。面板显示保存位置，“打开已存副本”可重新打开。
5. “重试预览”重新发布当前文档并重载，不重复应用修改或增加撤销记录。“重载并重播”重载当前已发布的快照。“重新打开源文件”可在修正源文件后重试打开。打开失败或打开后选择发射器失败时，面板不再保留上一个文档的参数与属性下标，编辑按钮在刷新出新文档的参数前不可用。

尺寸字段控制出生参数；文件里已有的 ScaleAnim 仍继续作用。例如把出生尺寸中心放大两倍，不一定会让某一年龄的最终尺寸严格乘二，因为动画的加法项没有随之改变。

当前单次修改到原生帧更新实测约 **5.23 秒**，主要仍是辅助进程重建；200 ms 目标未达成。连续修改会合并待加载目标，已开始的原生加载先结束，再加载最新目标，因此连续操作可能等待更久。

## 文档、发布和显示

LiveEditor 的 EditorEngine 是唯一文档和撤销权威。窗口中的数值只是带修订号的表单草稿，提交走现有 `set_fields` 邮箱协议。颜色与尺寸作为一个事务，Life 作为另一个事务；旧修订的草稿被拒绝。

默认会话位于 `runtime/re4-preview/<时间戳_GUID>/`，包含：

- `mailbox/`：独立后台状态与命令响应；与游戏内编辑会话分开。
- `mailbox/offline-preview/revision_*.efx.3539837`：经过完整文件保存/再读验证的不可变修订文件。
- `mailbox/offline-preview/preview.json`：原子发布的当前清单，包含文档标识、修订号、完整文件 SHA256、选中条目位置/ID及其新的字节偏移。
- `saved/`：用户保存的副本。

后台不传 `--game-root`，不轮询游戏进程，也不发布到游戏目录。游戏来源保持只读。会话目录在窗口关闭后保留，便于找回已发布或已保存文件；未提供跨重启恢复撤销栈的功能。`--session` 可指定一个新的会话目录，`--editor-backend` 可指定后台 DLL；它们不用于接管其他正在运行的后台。

面板分别显示“文档 rN”和“画面 rM”。只有新修订的原生帧成功读回后才替换旧画面；过时的加载/帧结果释放后丢弃。发布或加载失败保留已有文档和上一幅有效画面，显示错误，允许修正、撤销或重试。未应用草稿遇到外部修订会保持原值并要求刷新；干净表单会自动同步。程序监视本会话的清单变化，可接收同一后台通过邮箱协议完成的其他编辑，但没有自动接管游戏内或已有 MCP 会话。

发布失败不等同于编辑失败：编辑可能已经提交。响应中的 `offlinePreviewError` 会说明发布错误；调用 `publish_offline_preview` 只重发当前文档，避免重复修改。

## 验证

```powershell
dotnet run --project tools/Re4PreviewP2Tests
dotnet run --project tools/Re4PlaybackTests -- --native
dotnet run --project tools/Re4PreviewP1Tests
```

P2 集成测试使用真实 bb2 整个文件，覆盖：

- 序列化为完整 EFX、正确定位选中 entry，其他 entry 的内容不变；游戏原文件摘要不变。
- 颜色、尺寸和 ColorRate 到达实际原生粒子/属性块；Life 延长粒子寿命。
- 撤销恢复完整文件字节及同 tick 原生粒子数组 SHA256，重做可恢复修改。
- 保存、再读取、重新打开；保存到已打开的副本时按“导入来源受保护”拒绝（只认这一错误信息）；保存到游戏目录时窗口拒绝，保存到测试用受保护目录时后台拒绝，均不生成文件；拒绝旧修订。
- 无效 Life 区间：表单拒绝；绕过表单的原始 `set_fields` 被后台拒绝，修订号、发布摘要和 Life 参数不变。
- 人为锁住清单文件制造发布失败，修订和撤销记录保留；重试发布不重复编辑。
- 篡改已发布快照时 SHA256 校验拒绝加载；重新发布后原生预览可恢复。

真实窗口已操作颜色倍率输入（包括 Ctrl+A/粘贴）、应用、撤销、保存副本及打开副本；观察到 r2 的画面更新、r3 撤销恢复以及 r4 保存副本重载。连续外部发布 r5/r6 时，加载阶段保留 r4 画面，最终显示 r6，未被旧加载结果覆盖。数字编辑测试同时修复了共享 ImGui 控制器的修饰键事件上报。

原有 LiveEditor 剪贴板回归通过 57 项检查；为让当前后台可编译，旧测试中的 Life `r/s` 名称已改为当前 `min/max` 名称。常规 P1 原生与播放控制回归继续保留。

剩余渲染边界与 P1 相同：单 entry、BlendType 0/1，完整外观链和游戏录像对照未完成；完整分辨率一万粒子 60 fps 仍未达到。属性模块组装只保留在设计计划中，本阶段没有实现。
